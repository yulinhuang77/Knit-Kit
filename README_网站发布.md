# 纱线小喵 Knit Kit 网站发布版

这是从原始项目独立复制出的静态网站工程。原始项目位于 `D:\000chatgtp\1嵌花项目`，本目录及其子目录保存本网站的构建文件、发布包和日志。

## 内测与授权

纱线小喵 Knit Kit目前处于内测和持续完善阶段。织造计算、图案转换及操作指南仍可能存在误差。为避免尚未充分验证的结果用于商业活动并造成生产错误、材料损失或教学误导，本内测版仅免费开放给个人学习、研究和非商业手工制作使用。

允许个人学习、研究、设计和制作非商业作品，以及非盈利分享作品成果。收费设计、商业生产、收费课程、工作室批量使用、将生成方案用于销售产品、重新发布网站或修改版本，需要获得商业授权。

商业使用前仍必须进行人工复核和实际试织；授权不代表系统可以替代工艺确认。

## 数据说明

- 网站没有服务器账户和云数据库。
- 每位用户的项目、图片、图案和织造进度保存在其浏览器的 IndexedDB 中。
- 不同设备、浏览器或网址之间不会自动同步，请使用“导出备份”。
- 清除浏览器的网站数据会删除本地项目。
- PNG、JPG、PLT可以导入；PRJ、PRL、PLA需要先在ET中转换为PLT。

## 本地构建

在本目录运行：

```powershell
npm ci
npm test
npm run build
```

也可以双击 `构建网站.bat`。生产文件输出到 `dist`，同时生成发布压缩包。

## GitHub Pages 自动发布

上传整个 `DEMO2` 工程。`.github/workflows/deploy-pages.yml` 会在每次推送到 `main` 后自动执行：安装依赖、运行测试、构建源码、验证仓库子路径，最后发布已经审核确认的 `发布功能基线`。

首次上传后，在仓库网页进入 `Settings → Pages`，将 `Source` 设为 `GitHub Actions`。网站地址通常是：

```text
https://你的GitHub用户名.github.io/仓库名/
```

GitHub Pages发布不影响其他用户的浏览器功能，但从本地网址迁移到GitHub网址后，本地项目不会自动跟随网址迁移，需要先导出 JSON 备份，再在新网址导入。

## 更新流程

修改 `src` 后先运行测试和构建；确认完整功能后同步更新 `发布功能基线`，再推送到 `main`。GitHub Actions 会自动部署，历史提交可以用于回滚。

## 发布平台

- GitHub Pages：适合公开测试和静态展示。
- Cloudflare Pages、Vercel、Netlify：可上传 `dist` 静态文件。
- 面向中国大陆正式运营时，请根据所选国内服务商确认域名、服务器和ICP备案要求。
